# 答题页 2.0:以转换后的文档为基准,叠加交互层

日期:2026-10-21 · 状态:设计稿;**P0 自包含导出已实现**(见 §9),应用内 P1 未开工

## 1. 为什么要换

现在的题库链路是「提取正文 → 规则切题 → `_questions.json` → 答题页」。切题这一步必须**重新划分文档**,于是共享信息会被切丢。实测 CSP2019:

- 转换出的 Markdown 里,阅读程序一是完整的:小节说明、整段代码、判断题 1)–4)、选择题 5)6)(含选项);
- 而 `_questions.json` 里只剩小题,小节说明和代码上下文都不在题目上——答题时看不到「这段程序是干什么的」。

这不是某一条规则的 bug:**任何把文档重新排版成“题目卡片”的方案都会二次丢信息**。所以换基准。

## 2. 原则

1. **文档是唯一事实来源**:答题页以转换产物(HTML / Markdown)为正文,完整保留。
2. **交互是叠加,不是重排**:只在原文的题号、选项、括号、空位处插入控件;不复制、不改写正文。
3. **题库 JSON 降级为“交互索引”**:只记锚点(行号/块 id)、题型、选项标签、分组;**不存正文**。
4. **LLM 只做结构标注**:输出必须能锚回原文行号;校验不过就丢弃,不把模型文字直接渲染出来。
5. **没有 LLM 也能用**:确定性扫描先给出基础索引,LLM 只补“阅读程序/完善程序”这类需要语义分组的场景。

## 3. 数据契约:`uvreader.quiz-paper/v1`

```json
{
  "schema": "uvreader.quiz-paper/v1",
  "source": {
    "file": "CSP2019.pdf",
    "markdown": "CSP2019_doc.md",
    "html": "CSP2019.html",
    "hash": "sha1 of markdown",
    "engine": "engine",
    "extracted_at": "2026-10-21T..."
  },
  "sections": [
    { "id": "s1", "title": "二、阅读程序", "anchor": { "startLine": 89, "endLine": 200 } }
  ],
  "groups": [
    {
      "id": "g1",
      "kind": "reading_program",
      "title": "阅读程序一",
      "anchor": { "startLine": 91, "endLine": 160 },
      "context": { "codeLines": [91, 109], "noteLines": [89, 90] }
    }
  ],
  "units": [
    {
      "id": "u1",
      "kind": "true_false",
      "anchor": { "startLine": 113, "endLine": 113 },
      "groupId": "g1",
      "sectionId": "s1"
    },
    {
      "id": "u5",
      "kind": "single_choice",
      "anchor": { "startLine": 125, "endLine": 126 },
      "options": [{ "label": "A", "line": 126 }, { "label": "B", "line": 126 }],
      "groupId": "g1"
    },
    {
      "id": "u7",
      "kind": "fill_blank",
      "anchor": { "startLine": 142, "endLine": 142 },
      "blanks": [{ "index": 1, "marker": "（）" }]
    }
  ],
  "answers": [
    { "unitId": "u5", "value": "B", "source": "standard", "line": 388 }
  ]
}
```

约定:

- 所有行号是 **1-based、闭区间**,指向 Markdown 的原始行;
- `options` 只记标签和所在行,**选项文字从原文取**,避免两处漂移;
- `answers` 只在原文确有答案时出现(卷末答案区、题后「答案:」),并记来源行;
- 组(`group`)承载共享上下文:代码段、小节说明;判题时作为 context 一起送模型。

## 4. 构建流程

### 4.1 转换(已有)

`<源名>.md` + `<源名>.html`;图片相对路径在渲染时解析(答题页已实现)。

### 4.2 确定性扫描(无需 LLM)

按行扫描,产出候选:

- 题号:`1.` / `1)` / `1）` / `（1）` / `第 1 题`;
- 选项行:`A. … B. … C. … D. …`(同行或分行);
- 判断题:陈述句 + 结尾 `（）` / `( )`,且没有 A–D 选项;
- 填空:`____`、`（ ）`、`( )` 出现在句中;
- 小节:Markdown 标题 / `一、二、三、` / `- 判断题` / `- 选择题`;
- 代码块围栏:作为 `group.context.codeLines`;
- 答案区:`参考答案` / `答案:` / 卷末「参考答案与解析」。

产出的候选直接可用;不确定的边界留给 LLM。

### 4.3 LLM 结构标注(可选)

输入(**只给带行号的原文 + 候选 + 小节大纲**):

```
89: ## 二、阅读程序（…）
90:
91: ```
...
125: 5）若输入的字符串长度为 8，…至多有（）个字符不同。
126: A. 18 B. 6 C. 10 D. 1
```

输出:

```json
{
  "groups": [{ "id": "g1", "kind": "reading_program", "startLine": 89, "endLine": 160, "code": [91, 109] }],
  "units": [
    { "kind": "true_false", "startLine": 113, "endLine": 113, "groupId": "g1" },
    { "kind": "single_choice", "startLine": 125, "endLine": 126, "groupId": "g1", "options": ["A", "B", "C", "D"] },
    { "kind": "fill_blank", "startLine": 142, "endLine": 142 }
  ]
}
```

提示词要求:

- **只输出 JSON**;
- 行号必须来自输入,不得编造;
- 不复制正文,只给行号与标签;
- 一个 unit 的起止行必须完整包含题干/选项;共享题干放进 group,不重复。

校验(本地,硬门槛):

1. 行号在 `1..lines.length` 内,`start ≤ end`;
2. `options` 的标签必须在该 unit 范围内出现;
3. unit 之间不允许大面积重叠(允许嵌套:group 包含 unit);
4. 题号/选项数量与原文一致(选择题 ≥2 个选项);
5. 任一条不过 → 丢弃该 unit,保留确定性结果并写 warning。

### 4.4 缓存

`<源名>_quizmap.json`(与 md 同目录):

- key:md 的 sha1 + `promptVersion`;
- 失效:md 变了 / 提示词版本变了 / 用户点「重新识别」;
- 文档旁可读、可手改;答题页直接读它。

### 4.5 为什么不让 LLM 直接生成答题页 HTML

答题页最终确实是 **HTML/DOM**(阅读视图里由渲染器生成),但**生成者必须是我们的渲染器**,不是模型:

| 方案 | 问题 |
| --- | --- |
| LLM 直接输出整页 HTML | 会改写/漏掉正文;一次几万 token;无法校验;脚本/样式不可控;每次重渲染都要调用;主题/字号/缩放没法跟随阅读器 |
| LLM 输出**结构索引**(行号 + 题型 + 选项标签) | 体积几 KB;可校验、可缓存、可手改;正文永远取自原文;渲染由我们控制 |

所以分工是:

- **规则**:题号、选项行、`（）`、`____`、代码围栏、答案区——确定性的部分先做,覆盖大多数卷子;
- **LLM**:只处理规则不稳的部分——阅读程序/完善程序的共享题干、代码注释里的选项、题号重排、题型歧义;
- **渲染器**:把 Markdown 块 + 通过校验的索引变成带控件的 DOM/HTML;
- **判题**:复用现有 Q3,拿 unit 的行范围 + group 的代码作为上下文。

模型只允许输出"行号与标签",**任何正文都不允许来自模型**;校验不过就丢弃该条,回落到规则结果。这样既不需要手工把整份试卷"转换"一遍,也不会出现内容漂移。

### 4.6 结构标注提示词(规范)

````
你是试卷结构标注器。输入是带行号的 Markdown 原文。只输出一个 JSON 对象,
不要输出 HTML,不要复述原文,不要改写任何文字。

任务:找出所有"可作答单元",用原文行号引用它们。

约束:
1. unit.kind ∈ single_choice | multiple_choice | true_false | fill_blank | short_answer | program
2. anchor.start / anchor.end 是 1-based 闭区间,必须完整覆盖题干与该单元自己的选项;
3. 共享的题干、程序代码、小节说明放进 group,不要重复写进每个 unit;
4. options 只给 {label, line},不要给选项文字;
5. 原文没有标准答案时不要输出 answer / analysis,更不要编造;
6. 行号必须来自输入;不确定就不要标,宁缺毋滥。

输出:
{
  "sections": [{ "title": "...", "startLine": 89, "endLine": 220 }],
  "groups":   [{ "kind": "reading_program", "startLine": 91, "endLine": 160,
                 "code": [91, 109] }],
  "units":    [{ "kind": "single_choice", "startLine": 125, "endLine": 126,
                 "options": [{ "label": "A", "line": 126 }], "group": 0 }]
}
````

校验(本地硬门槛,不通过就丢弃该条):

1. 行号在 `1..lines.length`,且 `start ≤ end`;
2. 每个 option 的 `line` 在 unit 范围内,且该行确实以对应标签开头;
3. unit 之间不允许大面积重叠(group 可包含 unit);
4. 选择题至少 2 个选项,判断题不得带选项;
5. 模型输出的 `answer` 只有在对应行范围里能找到答案标记时才接受。

## 5. 渲染

### 5.1 正文

把整份 Markdown 按块渲染(标题、段落、代码、图片、表格),就像阅读视图;不做题目卡片重排。

### 5.2 交互注入

| 题型 | 原文形态 | 注入 |
| --- | --- | --- |
| 单选 | `A. … B. …` | 每个选项行变成可点行(保留原文文字),单选互斥 |
| 多选 | 同上 + 题干「多选」 | 可多选 |
| 判断 | 陈述句 + `（）` | 行尾加「对 / 错」两个按钮 |
| 填空 | `____` / `（ ）` | 原位插入输入框(空位旁),原文保留 |
| 简答/程序 | 题号 + 若干行 | 题尾出现「作答」区(textarea),可展开/收起 |

- 共享题干、代码、小节说明**只渲染一次**;小题只加控件,不再重复;
- 阅读模式 / 答题模式切换:阅读模式隐藏控件,便于对照原文;
- 答题卡:按 `section` 分组的题号格 + 状态(已答/答对/答错/未答);点题号滚动到锚点。

### 5.3 位置

保持现在的**阅读视图停靠侧栏**(可 toggle、可拖宽);由于要展示完整试卷,提供「整页」开关(占满阅读区,侧栏变成浮动答题卡)。整页模式不新增窗口,仍是同一个视图。

## 6. 判题

- 每个 unit 的文本 = `anchor` 行范围;上下文 = group 的代码/说明 + 所属小节;
- 有原文标准答案:选择/判断用确定性结论,模型只写解析;
- 没有标准答案:模型自己解题(沿用现有 Q3 提示词与 `judgements` 缓存);
- 标准答案来自 `answers`(原文锚点);模型给出的答案标记 `source: "ai"`,不写回原文。

## 7. 与现有题库的关系

| 场景 | 行为 |
| --- | --- |
| 有 `_quizmap.json` | 文档模式(推荐) |
| 只有 `_questions.json` | 退回复用现有题库卡片模式 |
| 都没有,但能拿到 md/html | 确定性扫描生成 quizmap,直接进入文档模式 |
| 只有 PDF、没有转换产物 | 先走转换(引擎优先),再扫描 |

`_questions.json` 仍保留给外部工具/兼容;新答题页不再依赖它。

## 9. 已实现:自包含答题页导出(2026-10-21)

`scripts/quiz-paper-preview.mjs` 现在就是导出器:

```powershell
node scripts/quiz-paper-preview.mjs <paper.md> <out.html> [--bank questions.json] [--answers answers.json]
```

- 正文来自转换后的 Markdown,控件按锚点注入;
- **答案来源优先级**:原文里的「标准答案 / 参考答案 / 试题解析」→ `--answers` → `--bank`;
- 答案写进 `data-answer` / `data-analysis`(隐藏字段),提交时本地判分:
  选择/多选/判断/填空自动判,主观题给参考答案自评;
- 判分后显示环形分数、答对/答错/未答/正确率/用时,逐题标对错并展示解析;
- **完全自包含**:图片转 data URL,公式用 `temml` 在生成时转成 MathML,页面不引用任何 CDN;
- 有答案的样卷:`docs/quiz-paper-python.html`(35 题自动判分);
  无答案的样卷:`docs/quiz-paper-preview.html`(CSP2019,提示无法自动判分)。

LLM 答案:先用模型生成一份 `answers.json`(`{"1":"C","2":"A",...}` 或 `{number:{answer,analysis}}`),再走同一个导出命令即可;页面本身不需要联网。

## 10. 风险与对策

- **模型编造**:只允许输出行号,渲染永远取自原文;校验不过就丢弃。
- **长文档**:按小节分块标注,块间用 section 边界拼接;单块 ≤150 行。
- **Markdown 保真**:现有渲染器已处理公式/图片/代码;图片相对路径已修。
- **性能**:整卷 45 题一次性渲染没有问题;更大文档按 section 懒加载。
- **迁移成本**:保留题库卡片模式作为回退,不破坏已有 `_questions.json`。
