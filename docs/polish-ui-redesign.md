# 精修界面重设计（草案）

> 状态：0.9.10 已实现左侧目录/全书概览、编辑器 + 预览/检查、底部状态栏、书籍信息弹窗、默认隐藏定位注释、整套精修 Markdown 导入/导出（带原书指纹）、编辑注号后自动顺延，以及书坊单条任务/精修工作区删除；marker 上标 chip、行号槽修正点圆点待做。

## 目标

- 主视图就是 **Markdown 编辑器 + 预览**，像正常的写作工具。
- 修正点、注文、目录检查退到辅助位置，不再常驻挤压编辑区。
- 保留电子书专用能力：加编号、加标注、删标注、重新生成正文标记、合并/删除注文、目录检查。
- 标注和内部定位注释不要抢视觉焦点。

## 现状问题

1. 三栏布局：修正点列表 + 编辑器 + 详情/预览。修正点和详情长期占掉两侧空间，编辑器不是主角。
2. 顶部有两排东西：筛选、阶段提示、五个操作按钮、更多菜单。信息层级太多。
3. 修正点列表常驻，让界面看起来像“问题工单系统”，而不是写作工具。
4. 编辑器里直接暴露 `<sup>1</sup><!-- polish:marker … -->` 这类内部注释，阅读和编辑都吵。
5. 预览被塞在详情栏下面，和修正点详情抢空间。
6. 没有全书目录导航，长书只能靠搜索或滚动；也看不到整本书的注文/标记/待确认总览。

## 推荐方案：双栏 + 右侧「预览 / 检查」

```

│ 105 已链接   │ 编辑器                                     │ 第一章 观察者             │

│ ▸ 第二章  ●  │  6                                         │ 这批人和其他不知名的…     │
│ ▸ 第三章     │  7  这批人和其他不知名的郯城人…¹⁰          │                           │
```

最左侧是新的**目录 / 全书概览 sidebar**，可以收起成一条窄 rail。它只负责导航和整体状态，不承担修正点处理。

右侧面板有两个 tab：

- **预览**（默认）：渲染当前光标所在章节。
- **检查**：修正点 / 注文 / 目录三个子页。

点顶栏「检查 94」或右侧「检查」tab，右侧切换到检查面板；再点「预览」切回来。编辑器和预览的相对位置不变，不出现第三栏。

### 检查面板

```
┌──────────────────────────────────────┐
│ 检查                        重新检查  │
│ [修正点] [注文] [目录]                │
│ 搜索注号、页码或注文…                 │
│ [待确认 94] [全部] [已处理]           │
├──────────────────────────────────────┤
│ ● 第一章 观察者：注号 26 没有正文标记 │
│   注释 · 待确认                       │
│ ● 第一章 观察者：注号 27 没有正文标记 │
│ ● 第二章 土地：注号 19 没有正文标记   │
│ …                                     │
├──────────────────────────────────────┤
│ 注号 26 没有对应的正文标记            │
│ 注释里的“第一章 观察者”分组有这条注文，│
│ 但该章正文没有找到对应标记。          │
│ 建议：在正文对应位置用“加标注”…       │
│ [去正文补标注] [查看注文] [标记已处理]│

```

- 列表和详情在同一个右侧面板里：上面滚动列表，选中后底部固定详情卡。
- 注文子页的详情卡提供：手动补号、与下一条合并、并入上一条、删除注文、查看正文。
- 目录子页只列高置信度问题，点击跳到对应章节；P0 不直接编辑目录。
- 检查面板默认收起，只有需要时才出现；顶栏的 `检查 94` 作为入口和未处理数量提示。

- 顶部「全书」区域给一个 overall view：章节数、注文数、已链接比例、待确认数、目录问题数。
- 目录按 `manifest.nav` 的层级缩进；当前光标所在章节高亮，并自动滚到可视区。
- 每章右侧显示注文数；有未处理修正点的章节加一个小圆点，不显示大数字，避免抢眼。
- 点章节：编辑器跳到该章标题；右侧预览跟随光标；如果当前在「检查」页，不强行切回预览。
- 收起后保留窄 rail：显示章节编号和当前章节高亮，点编号可直接跳章；点顶部「»」重新展开。
- 顶栏加一个 `☰` 按钮，和 sidebar 内的 `« / »` 都能切换；状态存进 `polish-session.json` 的 `ui.tocOpen`。
- 章节很多时，目录顶部出现章节搜索框；章节少时不显示，保持干净。
- 窄屏：目录变成左侧覆盖抽屉，顶栏 `☰` 打开，选完章节可自动收起。

### 目录来源与更新规则

- 左侧目录是**当前 `polish.md` 的实时 outline**，不是静态快照。
- 章节来自 Markdown 标题：`##` 为章，`###` 为节，`####` 为小节；`#` 是书名，不进目录。
- 顶部「层级」只控制**显示深度**（只看章 / 章 + 节 / 全部），不会改 Markdown，也不影响最终 EPUB 目录。
- 编辑标题、增删章节后，sidebar 自动更新；当前章节跟随光标高亮。
- 注释章里的分组标题（“## 前言”“## 第一章: 观察者”…）不进入左侧目录，避免 199 条注文把目录撑爆；注释章只显示一条，右侧可以看注文列表。
- 左侧目录只用于**编辑导航**，不是最终 EPUB 目录。
- 最终 EPUB 目录仍然使用书里的**印刷目录 / 清单 nav**；改名、删章时只重映射文件目标，不会按正文标题重建。目录检查在「检查 → 目录」。
- 建议在 sidebar 标题旁标一个「实时」小标记，避免和最终 EPUB 目录混淆。

### 书籍信息（封面 / 元数据）

入口：

- 左侧「全书概览」标题旁的 `⚙`
- 以及「更多 → 书籍信息…」

打开一个独立弹窗，两个 tab：

**封面**

- 当前封面预览
- 封面模式：模板生成 / 自动（书内首图）/ 指定图片 / 不要封面
- 模板配色
- 副标题
- 指定图片：选择图片…，显示方式（完整显示 / 铺满页面）

**元数据**

- 书名
- 作者
- 语言
- 标识符 / ISBN（可选）

保存后只更新 `polish.json` 里的 `book` / `build` 字段，不改 Markdown 正文；下一次「生成精修版本」使用新的封面和元数据。不会自动重建，也不会覆盖当前输出。

说明：当前清单里已有的是书名、作者、语言、标识符、副标题和封面配置；出版社、出版日期、简介这些字段暂不存，需要的话再加。

### 编辑工具栏

只保留和当前编辑动作直接相关的按钮，放在编辑器上方一条细工具栏：

- 补号
- 合并下一条（用户要求保留在主工具栏）
- 加标注
- 删标注
- 重新生成正文标记
- 显示/隐藏定位注释（可选，默认隐藏）

删除注文、并入上一条、手动补号等针对某条注文的动作，放在注文详情卡里，不占用主工具栏。编辑注号后，同一注释块里后面的注文和正文标记会自动顺延，不需要逐条改。

原来的「建议顺序：先核对注文编号，再检查正文标注」不单独占一排，收进检查面板顶部作为一句提示或小清单。

### 编辑器降噪

分阶段做：

1. **P0**：隐藏 `<!-- polish:note … -->`、`<!-- polish:marker … -->`、`<!-- polish:point … -->` 这些定位注释，编辑区只显示正文和普通 Markdown。
2. **P1**：把 `<sup>1</sup><!-- polish:marker … -->` 合并显示成一个轻量的上标小标记；点击标记可以在右侧打开对应注文。
3. **P2**：在行号槽用一个小圆点提示“这一行有修正点”，不展开、不抢眼；点圆点才打开检查面板。

P0 先保证编辑器看起来像正常 Markdown；P1/P2 是锦上添花。

### 顶栏

从左到右：

- 书名 + “整本书 Markdown”
- 保存状态（弱化，靠右）
- 检查按钮（带待确认数量）
- 更多
- 生成精修版本（主按钮）
- 关闭

筛选按钮（待确认/全部/已处理/全部注文）从顶栏移到检查面板。

### 状态栏

底部一条细状态栏：

`待确认 94 · 注文 199 · 标记 109 · 当前章节 第一章 观察者 · 已保存`

替代原来的顶部计数和阶段条。信息还在，但不再抢主视图。

## 视觉层级

1. **一级**：编辑器、预览。
2. **二级**：左侧目录/全书概览、编辑工具栏、检查入口。
3. **三级**：检查面板、修正点详情、注文详情。
4. **收走**：阶段条、常驻修正点列表、常驻详情栏、顶部筛选按钮。

## 响应式

- **宽屏**：编辑器 + 右侧面板（预览/检查）。
- **窄屏**：右侧面板变成全宽覆盖层；顶栏出现 `编辑 / 预览 / 检查` 三个切换，检查面板左上角有「← 编辑」返回。
- 检查面板在窄屏下是整页抽屉，不再挤成第三栏。
- 修正点/注文/目录三个子页各自使用自己的筛选：修正点「待确认/全部/已处理」，注文「全部/未链接/已链接」，目录「全部问题」。

## 分阶段实施

### P0：布局重排

- 移除三栏和阶段条。
- 主区域改成左侧目录/全书概览 + 编辑器 + 右侧「预览 / 检查」。
- 目录栏可收起成窄 rail，状态持久化。
- 检查面板整合修正点/注文/目录入口。
- 顶栏精简，计数移到状态栏和目录概览。
- 编辑工具栏只留 4 个主动作。

### P1：检查面板 + 书籍信息

- 修正点列表 + 详情卡在同一面板。
- 注文列表 + 注文详情动作。
- 目录问题列表。
- 搜索/筛选收进检查面板。
- 目录栏当前章节自动跟随、章节搜索。
- 书籍信息弹窗：封面设置 + 元数据设置，保存到 `polish.json`。

### P2：编辑器降噪

- 默认隐藏定位注释。
- 标记显示为轻量上标 chips。
- 行号槽修正点圆点。
- 可选“专注编辑”模式（隐藏行号/侧栏）。

## 待确认

1. 右侧面板默认显示「预览」还是「检查」？建议默认「预览」，有未处理修正点时在「检查」上显示数字。
2. 定位注释默认隐藏，还是提供一个开关？建议默认隐藏，工具栏提供“显示定位注释”。
3. 行号和折叠栏保留吗？建议保留行号，去掉折叠栏，减少左侧噪音。
4. 编辑工具栏的一级动作是否只留「补号 / 加标注 / 删标注 / 重新生成正文标记」？其它动作进注文详情和「更多」。
5. 目录 sidebar 宽屏默认展开还是收起？建议 ≥1200px 展开，<1200px 默认收起成 rail，并记住用户选择。
6. 书籍信息入口放左侧「全书概览」的 ⚙，还是顶栏「更多 → 书籍信息…」，还是两个都放？建议两个都放。
7. 元数据字段只做书名/作者/语言/标识符够吗？出版社、出版日期、简介要不要一起加？
