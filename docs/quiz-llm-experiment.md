# LLM 直接生成答题页:实验方案

日期:2026-10-21 · 状态:方案与提示词已定;待跑模型
对照基线:UV Reader 0.7.40 的确定性答题页(`buildQuizPaper`)

## 1. 实验问题

不是验证「LLM 能不能写一个像答题页的 HTML」,而是验证:

1. 在**不改写原文**的前提下,LLM 能否完成题目结构、控件、答案/解析和判分?
2. 对已经暴露过问题的真实文档,LLM 直接生成是否比规则解析更稳?
3. 如果能用,代价是什么(输出长度、延迟、费用、失败模式)?

## 2. 输入

提示词:`docs/quiz-llm-prompt.txt`

冻结以下真实 Markdown(从应用缓存/测试目录复制到 `experiments/quiz-llm/inputs/`,记录 sha256):

| id | 文档 | 特点 |
| --- | --- | --- |
| csp2019 | CSP2019_doc.md | 阅读程序、代码、判断题/选择题 |
| csp2020 | CSP2020_doc.md | 跨页代码、伪代码、q4/q5 合并历史问题 |
| csp2021 | CSP2021 merged.md | OCR 小节标题、连续代码块 |
| python1 | 202503python 一级.md | 35 题、答案完整 |
| c3 | 202503C语言三级/content.md | Word 参考程序、编程题 |
| testpdf2 | testpdf2.md | 答案/解析嵌在选项后、物理公式、图片 |
| testpdf2-c3 | 202503C语言三级.docx | (可选)同一份 Word 的另一路径 |
| clean | 一个短而干净的 5 题样例 | 排除长文档/抽取噪声的对照 |

每个输入保存:
- `source.md`(冻结)
- `images/`(仅记录文件清单与 hash;实验页面保留原路径)
- `meta.json`(来源、字节数、行数、图片数、代码块数、当前确定性答题页题数)

输入不做事先改写。另设一个可选变体 `normalized`:
- 只应用确定性预处理(页标记、跨页代码围栏、页边行号),不改变任何可见文字;
- 用于区分「提取/格式问题」和「LLM 结构问题」。

## 3. 模型与调用

- 首选 `deepseek-flash`(上下文 1M、输出上限 393k),`temperature=0`;
- 备选 `deepseek-v4-pro` 对比困难样本;
- 一次完整文档 = 一次调用;记录是否 `finish_reason=length`(截断);
- 同一输入至少跑 1 次;对失败/边界样本再跑 2 次评估稳定性;
- 保存:请求(不含 key)、原始响应、提取出的 HTML、usage、耗时、模型名、prompt hash。

## 4. 变体

| 变体 | 做法 | 目的 |
| --- | --- | --- |
| A: LLM 原始 Markdown | 直接把 source.md 放进提示词 | 最接近用户提议 |
| B: LLM + 确定性预处理 | 先跑现有 normalize,再给 LLM | 区分抽取问题与生成问题 |
| C: LLM 后处理 | A/B 输出后,本地 Temml 转 MathML、格式化代码、继续内联图片 | 看能否达到可发布质量 |

后处理脚本:`scripts/quiz-llm-postprocess.mjs`。它只改公式表示和代码缩进,不改正文文字;原始 `page.html` 保留,输出 `page.post.html`。
| Baseline | 0.7.40 `buildQuizPaper` | 内容/交互/答案对照 |

不建议让 LLM 直接输出整页作为最终生产方案;C 只是实验对照。

## 5. 自动检查

### 5.1 内容保真(硬门槛)

用 Playwright/Chromium 打开生成 HTML,对 `main#paper` 做 DOM 文本提取:

- 移除 `script/style/header/aside`、控件、隐藏答案/解析块;
- 保留选项、题干、代码、表格、图片 alt 的顺序;
- 与 source.md 的可显示文本做规范化比较(空白折叠,保留标点/公式原文);
- 计算字符/词级 recall、precision、编辑距离,并列出缺失/新增片段。

必须全部通过:
- 原文可见正文无缺失、无新增、无改写(允许 UI 文案在 `#paper` 之外);
- 代码块逐字符一致(换行/缩进/行号);
- 图片数量、顺序、`src`、`alt` 与 source 一致;
- 公式定界符/内容一致;
- 表格行列/单元格文字一致。

### 5.2 结构

- 题目数、题号集合、题型(选择/判断/填空/简答/编程)、选项数量;
- 每个题目是否有正确控件;共享代码/材料是否只出现一次;
- 原题号是否保持,没有重新编号;
- 与基线答案页的题目清单对照。

### 5.3 答案与解析

- 初始页面可见文本中不得出现 source 的答案/解析(允许存在于隐藏 DOM);
- 交卷后,每道有答案的题是否显示答案;解析是否只出现一次;
- 答案/解析是否仍在原位置,而不是被搬到页面底部;
- 选项文本中不得混入 `【答案】/【解析】/【详解】`;
- 本地判分:选择题/判断题/填空题抽样 100% 对;主观题不误判;
- 原文无答案的题:不得出现编造答案/解析。

### 5.4 交互与运行

- 无 JS 错误;无外部网络请求(图片/公式后处理除外);
- 选项点击、输入、交卷、二次交卷限制、计时/进度;
- 窄屏 375px / 桌面 1440px 不横向溢出;
- 图片在原位置、代码块完整、没有把正文重排成卡片墙。

### 5.5 成本与稳定性

- 输入/输出 token、耗时、失败/截断率;
- 输出 HTML 大小;
- 同一输入多次运行的题目数/内容差异;
- 单份文档成本估算。

## 6. 人工评审

- 每份文档至少看:首屏、每个题目控件、交卷后的答案/解析、代码/图片/公式位置;
- 重点看 CSP2020 q4/q5、CSP2021 阅读程序三、C3 编程题、testpdf2 答案/解析;
- 记录「可读但错」「内容正确但布局差」「内容丢失」三类问题。

## 7. 通过标准

**硬性失败**(任一即不推荐直接生产):

- 可见正文缺失/改写/新增;
- 代码/公式/图片被改;
- 答案/解析初始可见,或答案混进选项;
- 原文没有答案却生成答案;
- 输出截断或需要人工修补才能打开。

**建议门槛**:

- 6 份核心文档中至少 5 份通过内容保真;
- 题目/题型识别 ≥95%,无题号丢失;
- 有答案文档答案提取 ≥98%,解析 ≥95%;
- 无 JS 错误,离线可打开;
- 单份文档输出/耗时在可接受范围(目标 <3 分钟、<100k 输出 token)。

## 8. 预期与决策

根据提示词长度和文档规模,最可能的结果是:

- 短文档/干净文档:LLM 能生成可用页面,但容易漏细节;
- 长文档/OCR 文档:输出长、成本高,且更容易改写或漏段;
- 答案/解析、图片、公式这类「位置和字符」问题,LLM 仍不如确定性处理稳。

因此决策树:

1. A 在 6 份中 ≥5 份过内容硬门槛 → 可做「LLM 生成 + 本地后处理」的可选模式;
2. A 只有 ≤3 份通过 → 放弃整页生成,继续现有方案;
3. A 内容通过但交互/布局差 → 改做「LLM 结构标注 + 现有渲染器」;
4. 失败集中在长文档/输出截断 → 按 section 分块,但这会引入边界问题,需要单独验证。

## 9. 复现

```powershell
# 设置模型凭据(不要把 key 写进仓库)
$env:DEEPSEEK_API_KEY = "..."

# 单份
node scripts/quiz-llm-experiment.mjs `
  experiments/quiz-llm/inputs/testpdf2/source.md `
  --id testpdf2 `
  --model deepseek-flash `
  --out experiments/quiz-llm/runs

# 全量
node scripts/quiz-llm-experiment.mjs --all --model deepseek-flash
```

产物:

```
experiments/quiz-llm/runs/<id>/<model>/<timestamp>/
  prompt.txt
  response.raw.txt
  page.html
  meta.json
  metrics.json
  screenshot.png
```

`page.html` 保留模型原样(仅去掉外层 Markdown 围栏);`metrics.json` 由后续检查脚本生成,不修改页面内容。

## 10. 初跑结果(2026-10-21,deepseek-flash)

固定提示词 `docs/quiz-llm-prompt.txt`(v3:公式 MathML + 代码格式化);6 份输入全部一次生成,`finish_reason=stop`,没有截断。生成后再跑 `scripts/quiz-llm-postprocess.mjs` 做 MathML/代码收尾。

| 文档 | LLM 题数 / 基线 | 控件 | 图片 | 答案隐藏 | MathML / 代码 |
| --- | --- | --- | --- | --- | --- |
| CSP2019 | 43 / 43 | 152 个选项 | 1 / 1 | 无源答案 | 12 个 MathML;1 个代码块格式化 |
| CSP2020 | **43 / 43**(基线另有 1 个空题 B22) | 152 个选项 | 10 / 10 | 无源答案 | 32 个 MathML;3 个代码块格式化,1 个伪代码跳过 |
| CSP2021 | 43 / 43 | 153 个选项 | 1 / 1 | 无源答案 | 提示词 2 个 + 后处理 25 个;3 个代码块格式化 |
| Python 一级 | 37 / 37 | 120 选项 + 2 textarea | 7 / 7 | v2 通过 | 8 个代码块;试题编号等元数据仍按原文显示 |
| 202503C语言三级 | 5 / 5 | 5 个 textarea | 0 / 0 | v2 通过 | 5 个代码块已缩进 |
| testpdf2 | 15 / 15 | 40 选项 + 5 textarea | 21 / 21 | v2/v3 通过 | 111 个 MathML,0 个残留 `$...$` |

模型耗时约 **85–153 秒/份**,输出 **33–86 KB**。页面没有 JS 错误;图片请求在原始运行目录会因缺少 `mineru/images/` 报 `ERR_FILE_NOT_FOUND`,预览目录已复制图片。

### 观察

1. **版面可用**:短文档和结构清楚的 PDF 可以直接生成接近可用页;testpdf2 的答案块隐藏、5 个简答输入框、21 张图片和 15 张答题卡都成立。
2. **题数不能只看总数**:CSP2020 基线 44 个交互 unit,其中第 22 个是空题;LLM 生成 43 道真实题,实际没有少题。对照必须按题干/题号对齐,不能只比数字。
3. **答案标记必须在提示词里穷举**:v1 把 `标准答案/考生答案/试题解析` 留在页面;v2 明确这些标记后,C3/Python 不再显示。
4. **题内选项/非选择题**:testpdf2 q11 的小问 A/B/C 一度被模型变成整题选项;提示词补充「非选择题小节整题用 textarea」后恢复为 5 个 textarea。
5. **公式/代码仍建议后处理**:提示词 v3 让模型直接输出 MathML/格式化代码,但 CSP2021 仍有 25 个公式没转;Temml 后处理把它们补齐,并对代码做统一缩进。提示词负责结构,后处理负责确定性收尾。
6. **成本可控但质量余量不大**:每份 2 分钟左右、几十 KB 输出,一次不截断;空题/答案标记说明仍需要自动校验 + 重试。

### 结论(初跑)

LLM 直接生成 HTML **有可用性,但还没有达到生产门槛**。它适合做:

- 短试卷/干净 PDF 的快速原型;
- 现有确定性失败后的可选兜底;
- 结构标注(把结果交给现有渲染器)。

不适合当前直接替换规则方案:内容少题、答案标记、图片内联和可验证性都需要额外工程。

下一轮应先做:

1. 修 CSP2020 基线的空题 B22,并把题数对齐改成按题号/题干,而不是只比 unit 数;
2. 把 JSON 结构标注 + 现有渲染器作为对照组;
3. 把 MathML/代码后处理接入生成链路并做逐题内容校验;
4. 用硬门槛(内容零丢失、题目数一致)决定是否进入产品。

## 11. 与当前确定性答题页对照

| 维度 | 0.7.40 确定性方案 | LLM 整页方案(v3) |
| --- | --- | --- |
| 题数 | CSP2019/2020/2021/Python/C3/testpdf2 均覆盖;CSP2020 多一个空题 B22 | 六份题数均与真实题一致;CSP2020 无空题 |
| 题型/控件 | 规则识别,testpdf2 q11 曾有题内选项问题 | v3 后 testpdf2 5 个 textarea;仍可能把题内小问当选项 |
| 答案/解析 | 10 个答案、5 个参考、15 个解析(testpdf2);`data-*` 结构化 | 10 个 `data-answer`;答案/解析用隐藏块;解析不一定写入 `data-analysis` |
| 图片 | 生成时转 data URL,页面自包含 | 保留原始 `src`;实验运行页图片请求失败 |
| 公式 | 生成时 Temml 转 MathML | 提示词输出 MathML + Temml 后处理补齐 |
| 代码 | 现有格式化器;C3 参考程序带缩进 | 提示词格式化 + 后处理统一缩进 |
| 版面 | 文档模式 + 题目卡片,结构稳定 | 更接近整页试卷;v2 后卡片化减少,但仍不保证 |
| 自包含/离线 | 是 | 原始输出不是(需图片/公式后处理) |
| 运行成本 | 本地、毫秒级、可重复 | 约 2 分钟/份、几十 KB 输出、非确定 |
| 失败模式 | 规则覆盖不到的 OCR/版式边界 | 漏段、答案标记、位置/格式漂移 |

结论:**LLM 版在版面观感和题数覆盖上有优势,当前确定性版在可验证性、图片/公式/代码和答案结构化上明显更强。** 直接替换不划算;更合理的是「LLM 结构标注 + 现有渲染器」或「LLM 页面 + 本地后处理/硬校验」二选一,继续对照。
