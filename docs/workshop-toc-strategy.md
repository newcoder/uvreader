# 导航目录的生成策略(设计,2026-10-14)

用户提出的两条路线,评估结论:**可行,互补,建议按这个顺序做**。

## 路线 1:有印刷目录页 → 用印刷目录做导航(首选)

### 为什么这条路最好

- 印刷目录是**作者给的结构**:章节顺序、层级、标题写法都对,还包含前言/附录这类正文标题里没有的项;
- 我们**已经能识别**印刷目录页(`src/shared/printed-toc.js`,目前是"识别后丢掉");改成"识别后拿来用"即可;
- 一旦导航来自印刷目录,**正文里被误判的标题就不再影响目录**(「的努力？」那类碎片自动退出舞台)。

### 关键难点与对策

| 难点 | 对策 |
| --- | --- |
| **页码 ≠ PDF 页**(前置页偏移,如印刷第 1 页 = PDF 第 17 页) | 页码只当**提示**:用**标题模糊匹配**定位(先按页码附近找、找不到就全书找);匹配不到就保守丢弃并记日志 |
| 提取时 md 里**没有页信息** | 提取阶段插入**页码锚点**(`<!--page:17-->` 注释,EPUB 渲染时忽略),既服务匹配,也方便其它跨页逻辑 |
| 目录条目本身有 OCR 噪声(点线、串行、页码缺失) | 已有条目识别(点线/页码结尾);再加**校验**:页码非递减、标题能在正文找到;不合格条目丢弃而不是猜 |
| 多级目录(1.1 / 2.1.1) | EPUB nav 支持嵌套 `<ol>`;现有 `buildNav` 是平铺,需要扩成多级 |
| 目录页跨多页 / 分卷多份 | 收集所有被判定为印刷目录的页(连续段)合并使用 |

### 成本

- 提取阶段加页码锚点 + 多级 nav:`buildNav`/`buildNcx` 扩一层(半天);
- 印刷目录解析 + 匹配 + 校验(半天到一天);
- 面板:导航条目预览/编辑(复用现有目录编辑器,小改)。

## 路线 2:没有目录页 → 从 Markdown 自建 + **只对扫描件**做 LLM 跨页纠正

### 为什么只对扫描件

- **文本型 PDF 不需要**:PDF 文字层里的句子是完整的,`text-merge.js` 的跨页互补已经解决;
- **扫描件**才是硬骨头:每页独立 OCR,句子被分页截断,版式信号不可靠(已实测:文本信号与字号信号在真书上都会误伤真标题)。

### 设计(保守、可撤销)

1. **只收集"可疑点"**,不整本过:页首短行、不像标签式标题(第 N 章/§ 1/1.)、且规则判不了 → 生成一份**可疑清单**(典型一本书几个到几十个);
2. **只问一个问题**,三选一: `接上一句` / `独立标题` / `不确定`。只采纳**高置信的"接上一句"**,其余一律不动;
3. 走**现有 AI 配置**(伴读的 provider,本地端点优先),不加新设置;结果**按内容哈希缓存**,重跑不重复调用;temperature 0;
4. **可撤销**:面板列出"改了哪几处、为什么",一键还原(符合项目"可选可撤销"的一贯做法);
5. **默认关**,面板里勾选启用。

### 成本与风险

- 每次几十~几百 token(只处理可疑项),本地模型可离线;
- 风险:模型也可能判错 → 由"只采纳高置信 join + 只碰可疑点 + 可撤销 + 不碰标签式标题"四道约束兜底;
- 验收:拿已知样本(「的努力？」应判 join;`译者序`/`目录`/`集合论的一种公理化 ①` 应判独立标题)做回归。

## 建议顺序

1. **路线 1**(确定性、收益最大,且能顺带消掉假标题问题);
2. **页码锚点 + 多级 nav**(路线 1 的底座,也可独立价值);
3. **路线 2**(P2 的 LLM 步骤,只对扫描件、默认关、可撤销);
4. 体检脚本扩展:导航条目数、与印刷目录的一致率、可疑点清单。
## 责任划分:哪些是一般(reader)的,哪些必须 pdf_tool 做

原则一句话:**看数据在哪一层、谁判断得最可靠,就放哪一层;reader 只做「与提取器无关的书级策略 + 用户可见的交互」,并且永远保留兜底(上游没做也能用,但兜底只做确定不会误伤的部分)。**

| 能力 | reader(一般) | pdf_tool(上游) | 依据 |
| --- | --- | --- | --- |
| 页码 / 块顺序 / bbox / 字号 | ✗ | ✓ | 只有它能看到版式与页 |
| 页眉页脚 / 页码 / 水印清理 | ✗ | ✓(已做) | 同上 |
| 脚注正文 | 渲染 + 旧产物兜底 ✓ | 保留 `page_footnote` 块 ✓(aa752bc) | 数据在上游 |
| **印刷目录页** | 文本兜底识别 ✓ + 条目→锚点匹配/校验/生成 nav ✓ | **标记目录页(`page_role: toc`)+ 输出结构化条目 `[{title, page, level}]`** ← 需求 | 它认页更准;我们只兜底 |
| **页锚点** | 消费锚点(生成 nav、跨页判断) | **md 里插 `<!--page:N-->`(或保证 Doc JSON 每块 page 准确)** ← 需求 | 页边界它最清楚 |
| **跨页续行(扫描件)** | 规则兜底(谨慎)+ LLM 可疑点 ✓ | **块级标 `continuation: true`** ← 需求 | 页边界在上游;我们从文本猜已证伪 |
| 多页窗口 OCR/VLM | ✗ | ✓ ← 需求(根本解法) | 调 MinerU 的是它 |
| 标题判定 | 合理性过滤(虚词/短句/标签)✓ | 更保守的 `text_level` 或 `title_confidence` ← 可选 | 它先判,我们兜底 |
| 导航来源决策、去重、命名、EPUB 打包、多级 nav | ✓ | ✗ | 书级策略,与提取器无关 |
| LLM 编排(可疑点判定) | ✓(走已有 AI 配置,本地端点优先) | ✗ | 用户级配置不该让上游碰 |
| 面板/开关/可撤销/体检脚本 | ✓ | ✗ | 交互与可验证性 |

### 给 pdf_tool 的需求(按收益排序)

1. **目录页结构化**:标出目录页并给出条目(标题/页码/层级)。收益最大 —— 导航质量直接来自作者结构,顺带消掉「假标题进目录」的整类问题;
2. **页锚点**:md 里输出 `<!--page:N-->`(或保证 Doc JSON 的 page 准确),作为导航匹配与跨页判断的底座;
3. **跨页续行标记**(仅扫描件):块级 `continuation: true`。我们从文本猜过两套信号,在真书上都会误伤真标题,已撤回;
4. (长期)**多页窗口 OCR/VLM**:一次喂 2–3 页,让模型看见跨页句子 —— 扫描件的根本解法;
5. (可选)`title_confidence`:让上游给出「这行像标题」的置信度,我们据此决定是否让用户复核。

### reader 侧对应的工作(不依赖上游)

- 导航来源决策 + 多级 nav(EPUB nav/NCX 嵌套);
- 目录条目 → 锚点匹配与校验:页码只当提示(前置页偏移)、标题模糊匹配、失败条目保守丢弃并记日志;
- 可疑点清单 + LLM 判定(默认关、仅扫描件、可撤销、按内容哈希缓存);
- 兜底规则保留:印刷目录文本识别、碎片合理性、重复页眉/书名页;
- 体检脚本扩展:导航条目数、与印刷目录一致率、可疑点清单。

## 与现有代码的接口

- `src/shared/printed-toc.js`:现在是"识别 + 丢弃",要加"解析条目(标题/页码/层级)";
- `src/main/extract-doc.js`:提取阶段插入页码锚点;
- `src/main/epub-build.js`:`buildNav`/`buildNcx` 支持多级;
- `src/main/workshop-epub.js`:`book-build` 里决定导航来源(印刷目录优先,否则标题分章);
- 面板(向导 ②目录):显示导航来源与可疑点,提供编辑与还原。
