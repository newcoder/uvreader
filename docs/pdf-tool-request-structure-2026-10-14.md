# reader 侧需求:结构信息(目录页 / 页锚点 / 跨页续行)

日期:2026-10-14 · 来源:UV Reader 书坊(电子书向导)· 关联:导航目录策略

背景与责任划分见 reader 仓库 `docs/workshop-toc-strategy.md`。要点:**凡是「要看页面才知道的」判断都该在 pdf_tool 这一层完成**;reader 只做与提取器无关的书级策略(导航来源、去重、打包)与交互(面板、可撤销、体检),并且保留兜底 —— 所以下面每一条都是**收益项,不是阻塞项**。

## 1. 目录页结构化(收益最大)

**问题**:电子书的导航目录现在靠正文标题重建,于是版式模型把「上一页没写完的半句」判成标题时(实测「的努力？」),假标题就进了目录;而书里**本来就有作者给的印刷目录**。

**需求**:识别目录页并给出结构化条目。建议在 Doc JSON 里:

```json
{ "page_role": "toc", "page": 17, "toc_entries": [
  { "title": "第一章 光学简史", "page": 1, "level": 1 },
  { "title": "1.1 开场白", "page": 11, "level": 2 }
] }
```

- 页码用**印刷页码**(原书页脚上的数字)即可,不必换算成 PDF 页;
- 多页目录、分卷多份目录都按页标记即可;
- 条目 OCR 噪声(点线、缺页码)不用修,reader 侧会做校验(页码非递减、标题能在正文找到,失败条目保守丢弃)。

**收益**:导航目录直接来自作者结构,顺带消掉「假标题进目录」的整类问题。

## 2. 页锚点

**需求(二选一)**:

- md 产物里按页插入注释:`<!--page:17-->`(reader 渲染时忽略,只用来定位);或
- 保证 Doc JSON 里每个块的 `page` 准确(reader 自己插锚点)。

**用途**:导航条目 → 正文位置的匹配(印刷页码只当提示,真正定位靠标题模糊匹配 + 页锚点)、跨页判断。

## 3. 跨页续行标记(仅扫描件)

**问题**:扫描件没有文字层,句子被分页截断;reader 侧试过两套规则信号(上一页无句末标点 / 标题字号更大),在真书上都会误伤真标题(把 `译者序`、`目录`、`集合论的一种公理化 ①` 判成续行),已撤回。

**需求**:块级标记,例如 `{"type": "text", "continuation": true, "text": "的努力？"}`(表示它是上一页最后一段的续写)。判据由 pdf_tool 定(页边界、块顺序、缩进、行尾是否有标点等都在你这边);reader 只按标记合并。

## 4. 多页窗口 OCR/VLM(长期,根本解法)

一次喂 2–3 页(或整章)给 MinerU/VLM,让模型看到跨页的句子。这是扫描件跨页断句的根本解法,但属于上游调用方式,reader 侧无法替代。

## 5. 可选:标题置信度

`{"text_level": 2, "title_confidence": 0.62}` 之类,reader 可以把低置信度的标题**只放进「待复核」清单**(面板里让人确认),而不是直接当章节。

## 验收建议

- 用 reader 书坊的体检脚本(`npm run check:epub -- <file.epub>`)对比:导航条目数与印刷目录的一致率、假标题数、正文里未渲染公式数(现有指标);
- 目录页结构化可用《数学在科学和社会中的作用》做样本(目录在第 8 页附近,共 68 条)。
