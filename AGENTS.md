# UV Reader — agent notes

Obsidian plugin (`manifest.json` id `qiaomu-reader`) for EPUB/PDF/FB2/MOBI/AZW3/CBZ reading with highlights, notes and optional AI. UI copy, README and docs are Chinese-first. `src/main.js` is the plugin entry (~13k lines); the rest of `src/` is pure modules.

## Commands

- `npm ci` first; `postinstall` runs `patch-pdfjs.cjs` (idempotent pdf.js sentence-period fix, reverts on every fresh install).
- `npm test` — `node --test tests/*.test.mjs` (250 tests). One file: `node --test tests/core-config.test.mjs`; one test: add `--test-name-pattern="…"`.
- `npm run check:i18n` — dictionary, placeholder, HTML and URL parity across 9 languages, plus many exact-string assertions about `src/main.js`.
- `npx eslint src/ --max-warnings=0` — CI treats warnings as failures; only `src/` is linted.
- `npm run build` — cmaps → esbuild production → pdf.js patch; writes the committed root `main.js`/`styles.css`.
- `npm run verify:release` — version sync, bundle contents, licenses, font payload, CSS rules; optional install-dir argument compares hashes of an installed plugin.
- `npm run build:community` — community candidate in `dist/community/` (excludes the ACP dependency installer).
- `npm run dev` — esbuild watch (inline sourcemap); it also writes root `main.js`.

CI order (`.github/workflows/ci.yml`): test → check:i18n → build → verify:release → eslint → `git diff --exit-code -- main.js styles.css` → build:community. Reproduce this before committing.

## Committed build artifacts

- Root `main.js` and `styles.css` are generated but committed; Obsidian loads them and CI rebuilds and requires a byte-identical result. Never edit them by hand — edit `src/` and run `npm run build`.
- Windows trap: `scripts/foliate-elements.mjs:52` hashes the raw bytes of `package-lock.json` + itself to name foliate custom elements. With `core.autocrlf=true` a Windows build embeds a different `qbr-<hash>-foliate` prefix than CI and `git diff --exit-code -- main.js` fails. Normalize those two files to LF before building (`git config core.autocrlf false`, then delete and `git checkout --` them), then confirm with `npm run build; git diff --exit-code -- main.js styles.css`.
- `src/pdf-cmaps-data.js` is generated by `scripts/generate-pdf-cmaps.mjs`; do not edit.
- `verify:release` fails on `!important` or `:has(` in `styles.css`, on assets over 5.2 MB, and when `package.json` / `manifest.json` / `versions.json` versions disagree. `manifest.json` description stays English ending with a period; `package.json` description stays Chinese.

## i18n

- Default UI language is `zh`. UI strings go through `qiaomuReaderTranslate("…")`; literals are AST-extracted by `scripts/check-i18n.mjs`.
- A new UI string needs entries in `src/i18n-en.js`, `src/i18n-zh.js` and all 7 packs in `src/locales/`; `{0}` placeholders, HTML tags and URLs must match exactly.
- check-i18n and 15 test files assert exact substrings/regexes in `src/main.js`. Rewording or moving code there breaks the gates, so put testable logic in `src/*.js` modules instead.

## Architecture

- Tests run in plain Node (`node:test`, jsdom for DOM) and never import `obsidian`; only modules without Obsidian imports are unit-testable.
- foliate-js renders EPUB/FB2/MOBI/AZW3/CBZ; PDF keeps a separate pdf.js path (page image + official text layer). `DESIGN.md` is the binding design contract for the HUD, AI composer and PDF behavior.
- esbuild aliases node builtins and `localforage` to `build-stubs/empty.js`; `__PDF_WORKER_CODE__` and `__QBR_ENGINE_VIEW_TAG__` are build-time defines. Do not import node builtins from `src/`.
- When subclassing Obsidian `Modal`/`ItemView`, never overwrite framework fields — history filtering uses `filterScope` because `Modal.scope` is the keyboard scope (`tests/reading-workflow.test.mjs:114`); regress open, Esc and IME confirm when touching modals.
- `assets/starter-books/` are pinned Project Gutenberg sources (sha256 in `catalog.json`, `-text -whitespace` in `.gitattributes`); regenerate with `npm run build:books`, never hand-edit.

## Standalone desktop (M1)

- `packages/host-shim/` is the Obsidian API compatibility layer; `apps/desktop/` is the Electron shell. Plan: `docs/standalone-desktop-plan.md`.
- Root gates do not cover these directories. Run `node --test packages/host-shim/test/*.test.mjs` and `node --test apps/desktop/test/*.test.mjs` separately.
- Desktop setup: `cd apps/desktop && npm install` (behind a blocked network, set `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`), `npm run build`, `npm run dev`, `npm run smoke` (boots against a starter book and exits 0/1), `npm run e2e` (Playwright-Electron: page turn, highlight, reading note for EPUB and PDF).
- Desktop builds write to `apps/desktop/dist/` (gitignored) and must never touch the committed root `main.js`/`styles.css` by hand. `src/main.js` is shared by both hosts; desktop-only differences belong in the shim/shell, but when the plugin UI itself must change, edit `src/main.js` and rebuild the root artifacts (`npm run build`) before committing.

## Product interaction preferences

- Optimize for reading, highlighting and taking notes; minimize setup steps and cognitive load.
- Use progressive disclosure. Show service/model choices, required inputs and real readiness first. Fold paths, protocols, installation commands, response customization, storage internals and maintenance. Surface blocking errors with a specific recovery action.
- Prefer existing accounts, verified defaults, standard icons and short visible labels. Do not claim a connection works before checking it.
- Unnecessary hover tooltips are off by default, including Obsidian tooltips generated from `aria-label`, `setTooltip` and native `title`. Preserve accessible names with `aria-labelledby` or visually hidden labels, keyboard focus, visible slider values and useful error feedback. Do not hide tooltips globally or affect other plugins.
- A tooltip exception needs a concrete usability reason; do not add one just to repeat an icon label or visible text. Keep it scoped to the relevant control.
